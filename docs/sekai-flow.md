# タイトルとライブ開始の遷移

対象はセカイ体験版1.0.0 / 200005、arm64の既知バイナリのみ。2機能とも初期状態ON、起動互換修正がONの場合だけ適用し、設定はゲームプロセス起動時に読みます。

## タイトルのタップ

`TitleController.OnClickTitle` の状態2（AnimationRunning）または3（AnimationFinish）だけを対象にします。ロゴ表示中の0/1は純正のままです。タップ時に純正 `OnFinishTitleCall` でボイス終了ゲートだけを完了させ、既存の SoundManager のボイスを停止します。予約済みのタイトルコールは、専用の遅延コールバック入口で再生を抑制します。次のコール予約時に抑制状態をリセットし、管理対象オブジェクトのポインタは保持しません。

純正のタップ処理は維持します。状態2からの最初の処理が状態3になった場合に限り、同じ純正タップ処理をもう一度呼び、1回のタップで通常のログイン分岐へ進めます。アカウント有無、確認ダイアログ、認証通信、画面読み込みの完了は偽装しません。ログイン開始で純正コードがタイトルボタンを無効化します。

関数と共有ジェネリック呼び出しのABI、SoundManager用MethodInfoスロットは原版の命令から確認しました。Build IDと使用する関数の16 bytesを照合し、フック設置失敗時は設置済み分を戻します。

## 白いライブ遷移

`LiveTransitioner.Play` と `Finish` が `ColorFader.Play(Color, delay, duration, callback)` を呼ぶ2か所だけを対象にします。戻りアドレスとBL命令を照合し、元の delay=1秒、duration=1秒の場合だけ delay=0秒、duration=0.2秒へ置き換えます。HFA4のColor、完了コールバック、他の呼び出し元は維持します。

これにより白い演出の入口・出口の固定待機を取り除きます。ただし読み込み自体を高速化したり、準備完了判定を無条件に通したりするものではありません。ダウンロード、バックグラウンド準備、音声再生準備、1秒の音声準備後待機、音声遅延計測はそのままです。

`BaseLiveController.LiveStart` の別の6秒待機は、`OnMusicStart` が音楽を再開した後に入るため維持しました。ノーツ開始と音楽の同期を変えないためです。実際の白画面の短縮量はデータの読み込み時間によって変わります。

## 検証範囲

静的解析で原版の分岐・引数・命令を確認し、ホスト試験でタイトル状態の対象範囲、二重処理の条件、2か所だけへの遷移短縮を確認します。releaseビルド、Lint、署名・構造検証を行います。実際のタイトルタップ、再入場、ライブの音声同期・完走は未確認です。ゲームの再起動や画面操作は実施していません。
