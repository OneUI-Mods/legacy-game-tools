# タイトルとライブ開始の遷移

対象はセカイ体験版1.0.0 / 200005、arm64の既知バイナリのみ。両機能は初期状態ONで、起動互換修正がONの場合だけ適用し、設定はゲームプロセス起動時に読みます。

## タイトルコール

タイトルコール予約から終了まで、TitleControllerをGC弱参照で追います。UnityPlayer.windowFocusChangedでゲームのフォーカスを確認し、ゲームがフォーカスを持つ間だけ、Unity EventSystemの更新後にAndroidタッチ開始またはマウス互換入力を確認します。予約後に一度指が離れてから補助判定を有効にし、持ち越した入力を拾わないようにします。TitleStateがAnimationRunning(2)かAnimationFinish(3)の場合だけ通常のタイトル処理へ渡し、ロゴ表示中の0/1は扱いません。ボタンのクリック通知だけでは入力を取りこぼす場合があるための補助経路です。

予約中にスキップした場合は、専用の遅延再生コールバックで後から音声が始まらないようにします。再生中は、ゲーム自身のSoundManager.PlayVoiceの戻りアドレスを照合し、実際のSoundManagerと返された再生IDだけを保持します。タップ時にはそのIDをSoundManager.Stopへ渡します。他の音声をまとめて停止しません。管理オブジェクトの参照にはGCハンドルを使います。

スキップでは純正OnFinishTitleCallで音声の終了ゲートを完了させます。純正タップ処理の最初の呼び出しで状態2→3となった場合だけ、同じ純正タップ処理をもう一度呼び、1回のタップでログイン分岐へ進めます。アカウント有無・確認ダイアログ・認証通信・データ準備の完了は偽装しません。

### rc3/rc4のクラッシュ

実機の23:02および23:14の記録で、追加処理からCP.SingletonMonoBehaviour.get_Instanceを直接呼び出した後、0x26792f8でnull参照が起きていました。必要なジェネリックの具体化情報を安全に渡せていなかった呼び出しを撤去しました。rc5はこの共有getterとMethodInfoスロットを利用せず、元のゲームの再生呼び出しから音声管理オブジェクトを取得します。

## 白いライブ遷移

LiveTransitioner.PlayとFinishがColorFader.Playを呼ぶ2か所だけを対象にします。戻りアドレスとBL命令を照合し、元のdelay=1秒、duration=1秒の場合にdelayのみ0秒へ変更します。**durationは純正の1秒のまま**です。Color、コールバック、他の呼び出し元を変更しません。rc3/rc4の0.2秒フェードは撤去しました。

データ読み込み・音声準備・1秒の音声準備後待機・音声遅延計測は維持します。ロードそのものの高速化や、準備フラグの偽装はしません。

## ソロライブの6秒待機

純正LiveStartコルーチンがMusicReadyを実際に完了してOnMusicStartを実行し、状態4へ入ったときだけ対象とします。同じ呼び出しでLiveTransitioner.Finishが始めたColorFaderのFadingを観測できた場合、6秒のWaitForSecondsを次フレームの繰り返し待機へ置き換えます。

同じフェーダーの状態がFadingからNoneへ戻り、同じ遷移表示の純正Destroy処理が実行されたことを確認します。Unityの破棄が反映される次フレームを待ってから元の状態4を再開します。フェードだけ先に終わっても待機は続けます。遷移表示をここでDestroyする処理は撤去し、純正の終了タイミングと粒子演出の寿命を保ちます。音声遅延計測と通常のRhythmGameStartは元の処理を通り、曲の再生位置・ゲーム時刻は書き換えません。SoloLiveControllerだけが対象で、他のコントローラーの待機は維持します。

完了を観測できない場合は元の6秒相当（Unityのスケール済み時刻）で復帰します。最初にフェード開始を観測できなければ元のWaitForSeconds自体を残します。失効した弱参照を完了と見なしません。

## 検証

対象Build ID、使用する関数のプロローグ、呼び出し命令を検証します。ホスト試験はタイトル状態・追加タップの条件・指定された遷移呼び出しだけへの適用・フェード長の保持・OFF時の転送・待機判定とフォールバックを確認します。

実機試験の詳細は[検証記録](sekai-flow-validation.md)へ記録します。共有getterの直接呼び出しは再導入しません。
